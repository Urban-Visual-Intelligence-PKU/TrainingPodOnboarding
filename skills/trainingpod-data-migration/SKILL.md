# TrainingPod 数据迁移

1. 确认使用者的目录名、源目录以及获准共享的具体子目录。用只读操作清点文件，检查隐藏文件、符号链接、预计空间和仍在写入的任务。将个人资料归到 `/fsx/<姓名>`，将获准共享的原始下载数据归到 `/fsx/shared/data/raw/<数据集>`，保留原始内容。将获准共享的清洗、转换、切分或其他项目产物归到 `/fsx/shared/data/<项目名>/<数据集>/`，同时记录来源数据版本和处理方式。`raw` 是保留目录名。排除密钥、令牌、`.env` 和任何尚未确认可公开给预期使用者的内容。记录共享数据的来源、版本和使用许可。
2. 在宿主机上处理 `/home/<账号>` 中的源。请管理员确认 `findmnt -M /fsx` 指向持久存储，并创建个人根目录或配置共享目标父目录的 ACL。确认实际搬运身份可以访问源和目标，目标目录名尚未使用，符号链接不会指向其他容器读不到或无权访问的位置。无法确认时，先完成能做的清点并报告具体缺项。
3. 按用户授权的范围执行移动。先协调停止源目录的写入。同一文件系统内优先在宿主机用 GNU `mv --no-clobber --no-target-directory -- "$src" "$dst"`，其中 `src` 和 `dst` 为已核对的绝对路径。迁移前用 `stat -c %d` 比较源与目标父目录的设备编号，检查目标路径及同名符号链接。迁移后检查源已经移走且目标存在，因为 GNU `mv --no-clobber` 跳过已有目标时可能仍返回成功。跨文件系统时先分阶段迁移并校验文件内容与权限，经用户授权后再清理源。
4. 整目录移动会带着原有权限和 ACL。请管理员按共享范围检查并调整现有目录和文件的权限，同时为后续新文件配置默认 ACL。从用户的 Pod 读取代表性文件。若要共享给其他 Pod，再从一个获授权的 Pod 验证读取，约定可写时验证能创建并删除测试文件。
5. 更新任务配置中的数据路径并做一次小规模读取验证。向用户报告源与目标路径、是否已移动、权限和读取的实测结果，以及仍需管理员处理的事项。
